# Certificate Portal

Production-oriented, mobile-first certificate verification and administration app built with React + Vite + TypeScript, Tailwind CSS, Supabase, XLSX and jsPDF.

## Architecture

- Public route `/`: lightweight certificate search, preview and on-demand PDF generation.
- Hidden admin route `/secure-admin-panel`: Supabase Auth protected dashboard.
- Supabase Postgres: certificates, templates, downloads and admin activity.
- Supabase Storage: certificate template artwork.
- Browser canvas + jsPDF: overlays the exact recipient name on the original template without rebuilding the artwork.
- Realtime: download activity subscription for the admin dashboard.

## 1. Create Supabase

Create a new Supabase project. Open **SQL Editor** and run the complete migration at:

`supabase/migrations/001_initial.sql`

This creates the database schema, indexes, triggers, RLS policies, secure download RPC, certificate ID generator, realtime publication entry and the `certificate-templates` storage bucket.

## 2. Create the admin account securely

Create a user in **Supabase Dashboard → Authentication → Users** with the admin email and password you want to use. Do not put the password in this repository.

Then, in the Supabase SQL Editor, set the user's `app_metadata` role to `admin` using the user's UUID:

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || jsonb_build_object('role','admin')
where id = 'YOUR-USER-UUID';
```

The frontend checks only the authenticated user's server-issued JWT metadata. Sensitive operations are also protected by RLS.

## 3. Environment variables

Copy `.env.example` to `.env.local`:

```env
VITE_SUPABASE_URL=your-project-url
VITE_SUPABASE_ANON_KEY=your-anon-key
```

Only the public Supabase URL and anon key belong in the browser. Never add `SUPABASE_SERVICE_ROLE_KEY` to a Vite `VITE_*` variable.

## 4. Install and run

```bash
npm install
npm run dev
```

Build for production:

```bash
npm run build
npm run preview
```

## 5. First template

1. Sign in at `/secure-admin-panel`.
2. Open **Template Manager**.
3. Upload the original PNG/JPG certificate artwork.
4. Select the template.
5. Drag the `TEST NAME` box to the exact name location.
6. Resize it using the corner handle.
7. Select font, weight, size, alignment, color and letter spacing.
8. Save the configuration.
9. Activate the template.

The original artwork is never regenerated or redesigned. PDF generation rasterizes the unchanged artwork and overlays only the recipient name.

### Font matching

The editor includes common print-safe fonts. If the certificate uses a specific font not listed, add a TTF/OTF font upload flow to the template record using the `font_file_url` column and load it with the browser `FontFace` API before canvas rendering. This is the preferred route when exact typography is required. The current baseline keeps the dependency set small and lets the editor select the closest configured font without modifying the template artwork.

## 6. Import Excel

Open **Import Excel**, upload `.xlsx`, `.xls`, or `.csv`, select the name column, inspect the preview, and confirm the import. Names are stored exactly as supplied. Certificate IDs are generated by a database sequence and are not client-controlled.

## 7. Public download

A user can search by certificate ID or exact recipient name. The public route returns only the minimum certificate result through the `search_certificate` RPC. The browser then loads the active template and generates a PDF on demand.

## 8. Vercel

Import the repository into Vercel. Add:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

Build command: `npm run build`

Output directory: `dist`

`vercel.json` rewrites SPA routes to `index.html`.

## Security notes

- No admin password is present in frontend source.
- No service-role key is used by the frontend.
- Public certificate retrieval uses a restricted RPC rather than direct table access.
- Admin database operations require Supabase Auth plus `app_metadata.role = admin` through RLS.
- Download tracking is inserted through a security-definer RPC rather than an open insert policy.
- Destructive admin actions require a confirmation in the UI.
- File-size and file-type checks are enforced in the browser; production deployments should also enforce storage limits and MIME restrictions in Supabase Storage settings.

## Important production hardening

For exact custom-font matching, upload and persist the certificate's original TTF/OTF font and load it with `FontFace` before rendering. For very large imports, batch inserts rather than sending thousands of rows in one request. For very large certificate sets, keep pagination and indexed searches enabled.

## New operational features

- Live admin dashboard with active/live certificate count, download totals, today/week/month metrics, unique downloaded certificates, templates, and feedback counters.
- Realtime download activity using Supabase Realtime; no one-second polling loop.
- Public feedback form at `/feedback` with a simple 1–5 rating and optional certificate ID.
- Protected admin Feedback page for reviewing and marking feedback as read.
- Server-side `admin_dashboard_stats()` RPC keeps dashboard queries compact and fast.
- Public feedback is inserted only through a constrained database function; public users cannot read or modify feedback.
- Mobile-first visual polish with a restrained SaaS design system and lightweight responsive cards.

## IMPORTANT: Enable the admin account

Supabase Auth password login and application authorization are intentionally separate. After creating the admin user in **Authentication → Users**, run this in the Supabase SQL Editor, replacing the email with the exact admin email:

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || jsonb_build_object('role', 'admin')
where email = 'YOUR_ADMIN_EMAIL';
```

Then sign out and sign in again. The application checks `app_metadata.role = admin` both before entering the dashboard and in the database RLS policies. The admin password is never stored in the frontend.

### If login succeeds but the dashboard redirects back to login

This means the Supabase password is correct but the user is not authorized as an admin. Run `supabase/admin-setup.sql` in the Supabase SQL Editor, replace `YOUR_ADMIN_EMAIL`, then sign out and sign in again. The app intentionally does not treat every authenticated user as an administrator.

## Admin login — one-time setup

1. Create an account in Supabase Dashboard -> Authentication -> Users.
2. Open `supabase/SETUP_ADMIN.sql`.
3. Replace `YOUR_ADMIN_EMAIL` with the exact email used for that Supabase Auth account.
4. Run the complete SQL file in Supabase SQL Editor.
5. Confirm the result shows `role = admin`.
6. Sign out of the website, close the tab, reopen `/secure-admin-panel`, and sign in again.

The frontend never contains the admin password or Supabase service-role key. The application refreshes the Supabase session after login so newly-added `app_metadata.role` is picked up immediately.
